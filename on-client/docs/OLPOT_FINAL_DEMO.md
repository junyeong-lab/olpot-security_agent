# olpot 완성본 시연 순서 및 최종 정리

> **기준일:** 2026년 10월 28일  
> **프로젝트:** olpot — 개인 PC 상태 관제 대시보드  
> **화면 구성:** 위쪽 상태 카드 **4개**, 아래 실측 변화 비교·추이·기록  
> **실행 방식:** 기존 Workbench 프로젝트 폴더에서 직접 실행. **앱 포장하지 않음**  
> **근거 구분:** 실제 사용자 화면·실행 기록 / GitHub 소스 확인 / 모의 테스트 / 확인 불가

## 1. 시연 목적 및 범위

olpot은 ALEPH 보안 Agent 시작 틀의 제공 기능을 유지하면서, **본인 Windows PC의 읽기 전용 측정 결과를 학생 영역에서 비교·정리**하도록 개선한 프로젝트다. 측정과 화면 표시는 다른 역할이다. **PC 데이터 수집 API 자체나 제공 공통 화면을 직접 개발했다고 주장하지 않는다.**

이번 시연의 세 핵심 기능은 다음과 같다.

1. **PC 실측 변화 비교:** 서로 다른 시각의 CPU·메모리·디스크 및 Windows 기록 집계 차이를 비교한다.
2. **CPU·메모리 실측 추이:** 현재 페이지에서 수동 조회한 결과의 시각별 기록을 나열한다.
3. **기록·출처·다음 행동:** 상단 네 개 상태 카드와 연결 상태, 측정 출처, 확인 불가 사유 및 후속 행동을 설명한다.

수집한 Windows 경고·오류 건수는 침입 탐지 결과가 아니며, 방화벽 설정이 켜져 있어도 PC 전체의 안전을 입증하는 것은 아니다.

## 3. 완성본 시연 순서

### 준비 — 기존 프로젝트에서 실행

1. Windows에서 기존 `olpot-security_agent\on-client` 폴더가 존재하는지 확인한다.
2. PowerShell에서 `node --version`으로 지원 범위 **Node.js 22~24**를 확인한다. 수업 기준은 24.19.0이다.
3. **6장 실행 명령**으로 기존 앱을 켜고 `http://127.0.0.1:5189/`에 접속한다.
4. 「보호 현황」의 **olpot · 내 PC 관제** 영역을 보여 준다. 처음에는 `미측정` 또는 `확인 불가`가 보일 수 있으며 이를 오류나 안전 판정으로 단정하지 않는다.

### 핵심 기능 ① — PC 실측 변화 비교

1. 상단 네 카드(네트워크·방화벽·Windows 기록·SDP 상태)를 먼저 가리킨다.
2. **「다시 조회」**를 눌러 첫 번째 측정 결과를 기록한다. PC 실측 자료는 제공된 `/api/pc/status`에서 온다.
3. 서로 다른 측정 시각에 같은 버튼을 다시 눌러 두 번째 결과를 기록한다.
4. **① PC 실측 변화 비교** 영역에서 CPU 사용률(%p), 메모리 사용률(%p), 디스크 여유 공간(GB), Windows 경고·오류 건수(건)의 **이전/최근 시각과 차이**를 설명한다.
5. 자료가 하나뿐이거나 특정 항목이 누락되면 숫자를 만들지 않고 `확인 불가` 또는 비교 대기로 표시하는 원칙을 설명한다.

### 핵심 기능 ② — 실측 추이

1. **② CPU·메모리 실측 추이** 영역으로 이동한다.
2. 실제로 수동 조회한 시각별 CPU·메모리 수치와 단위를 확인한다.
3. 추이는 최근 **최대 12회, 현재 페이지 메모리 한정**이며 미측정 구간의 값을 임의로 보간하지 않는다는 점을 말한다.
4. 새로고침하면 이력이 초기화됨을 한계로 설명한다. 실제 시연 중 초기화 여부를 확인할 경우에는 그 결과만 추가 기록한다.

### 핵심 기능 ③ — 기록·출처·다음 행동

1. 위쪽 **Windows 기록 카드**에서 System·Application의 최근 24시간 경고·오류 집계를 확인한다. 최대 **5,000건** 조회 한계 및 부분 집계 여부를 구분한다.
2. **SDP 상태 카드**에서 `SDP 미연결` 또는 `연결 확인 불가`가 PC 측정 성공과 분리된 것을 확인한다.
3. **③ 기록·출처·다음 행동**에서 읽기 전용 측정 출처, 측정 시각, 보존되는 임시 이력의 범위를 확인한다.
4. 실패 사례는 실제 PC에서 발생한 경우에만 `확인 불가`, 실패 항목, 이유, 다음 행동을 **실제 실패 화면**으로 설명한다. 실제 오류가 없다면 **코드·모의 테스트로 검증한 동작**으로 따로 소개한다.
5. `Tab`으로 「다시 조회」 버튼에 이동한 뒤 `Enter`로 실행한 **실제 사용자 키보드 검증**을 언급한다.

## 4. 실제 확인한 근거

### A. 실제 PC 화면 — 2026년 10월 28일 사용자 제공 캡처

다음 값은 **그날 화면에 표시된 과거 실측 결과**이다. **현재 PC 수치나 설명용 가상 값이 아니다.**

| 항목 | 당시 사용자 화면에서 확인한 결과 | 해석의 한계 |
|---|---|---|
| 네트워크 | 인터페이스 **2개**, IPv4 구성 **2개** | 인터넷 접속 가능·업무망 접근 허용의 증거가 아님 |
| Windows 방화벽 | Domain·Private·Public **켜짐** | PC 전체가 안전하다는 판정이 아님 |
| Windows System·Application 기록 | 최근 24시간 **경고 12건, 오류 14건** | 악성코드·침해 발생 건수로 읽지 않음 |
| CPU 사용률 | **10.4% → 11.1%, +0.7%p** | 서로 다른 두 시각의 사용률 차이 |
| 메모리 사용률 | **53.5% → 53.5%, 표시상 +0.0%p** | 표시 자릿수 기준의 변화 |
| SDP | **미연결** | PC 로컬 측정과 원천 SDP 연결은 별도 |

캡처는 대화에서 사용자가 제공해 확인한 화면이다. **이 캡처 파일이 GitHub 저장소나 본 문서에 첨부되었다고 주장하지 않는다.**

### B. 사용자 실행 기록으로 확인한 사실

- 기존 Windows Workbench 프로젝트 폴더에서 로컬 서버를 실행하여 **5189** 브라우저 화면이 열림.
- 4일차 관제 대시보드 상단 **4개 카드**와 세 핵심 기능 영역이 실제 표시됨.
- 「다시 조회」 후 **두 시점의 실측 비교**가 사용자 화면에 표시됨.
- 사용자가 **`Tab` → `Enter`로 조회 실행**했다고 직접 확인함.
- **실제 실행 중 막힌 단계는 없었다**고 사용자가 보고함.
- 로컬 `git hash-object` 조회 결과가 GitHub 4일차 학생 파일의 blob 해시와 일치함:
  - `student/extension.mjs`: `df94a1dddf2dd7ecd2759f97f35be0ae0965dba9`
  - `student/appearance.json`: `11652c06f0a2259309248af0aba74587bc6b5151`

### C. 코드·모의 테스트 결과 — 실제 PC 오류 재현과 구별

4일차 코드 점검에서 모의 API/DOM 응답으로 다음 경로를 확인했다.

- 조회 중 `조회 중…` 표시, 중복 요청 차단, 조회 전후 키보드 포커스 유지
- 방화벽 권한 부족 및 Windows 기록 조회 시간 초과 시 **개별 실패 이유·다음 행동** 표시
- 전체 조회 실패 시 과거 값을 **이번 현재 실측값으로 승격하지 않음**
- 조회 전 자동 로컬 요청 없음, 상단 **4개 카드**와 하단 비교·추이·기록 순서
- 13~22단계의 기존 학생 렌더 함수 보존, GitHub 변경 범위 점검

이들은 **실제 Windows PC에서 각각 장애를 재현했다는 증거가 아니라, 코드와 모의 테스트의 증거**이다. `Space` 키 조작 및 실제 화면의 순간적인 대기 표시 역시 실제 PC 실측 화면으로 확인했다고 쓰지 않는다.

## 5. 남아 있는 한계와 확인 불가

| 구분 | 상태 | 정직한 설명 |
|---|---|---|
| SDP 원천 연결 | **시연 당시 미연결** | 로컬 PC 조회 성공을 SDP 연결 성공으로 표현하지 않음 |
| 실제 XDR 공격 탐지·대응 효과 | **미검증** | Windows 경고·오류 집계는 XDR 침해 탐지와 다름 |
| PC 전체의 보안 안전성 | **판정하지 않음** | 방화벽 ON 및 CPU 상태만으로 안전하다고 결론 내리지 않음 |
| 측정 이력 저장 | **임시 기록만 구현** | 최근 12회, 페이지 새로고침 시 초기화. 영구 저장 미구현 |
| 실제 PC의 권한 부족·시간 초과 장애 | **실제 재현 근거 없음** | 모의 테스트 확인과 구분 |
| 다른 사용자의 다른 PC 재현 | **별도 독립 실행 기록 없음** | 현재 PC 사용자 성공 기록은 있음. 미검증이 이번 사용자 실행의 실패를 뜻하지 않음 |
| 설치형 앱 실행 | **미실시, 작전 범위에서 제외** | 포장 명령과 새 포장 스크립트 모두 사용하지 않음 |
| 학생 변경의 `main` 반영 | **반영되지 않음** | 작업 브랜치 SHA를 명시. 다른 브랜치를 잘못 시연하지 않음 |

조회 실패는 `0`, `정상`, `안전`으로 대체하지 않는다. 예시 수치를 실제 PC 실측값으로 제시하지 않는다.

## 6. 실행 명령 및 재현 확인 순서

**기존 작업 폴더:** `%LOCALAPPDATA%\ALEPH\Workbench\projects\olpot-security_agent\on-client`

PowerShell 어느 위치에서나, 해당 경로에 프로젝트가 있는 기존 PC에서 실행:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\ALEPH\Workbench\projects\olpot-security_agent\on-client\tools\start-alekov.ps1"
```

1. `node --version` → 지원 버전인지 확인. **추가 패키지 설치 또는 앱 포장 명령은 실행하지 않음**.
2. 브라우저에서 **http://127.0.0.1:5189/** 열기. 이미 서버가 있다면 중복으로 실행하지 않음.
3. **보호 현황 → olpot · 내 PC 관제 → 상단 상태 카드 4개** 순서 확인.
4. **「다시 조회」**를 눌러 첫 번째 측정 후 다른 시각에 다시 눌러 두 번째 측정. 이번에 나온 **실제 값과 측정 시각·단위**를 사용.
5. **① PC 실측 변화 비교 → ② CPU·메모리 추이 → ③ 기록·출처·다음 행동** 확인.
6. 네트워크·방화벽·Windows 기록의 근거와 **SDP 원천 연결 상태의 분리** 설명.
7. 실제 장애가 없으면 실패 화면을 만든 척하지 않음. 설명용 예시가 필요하면 **"설명용 예시 · 실제 조회 결과 아님"**으로 표시.
8. PowerShell 서버 창에서 **`Ctrl+C`**로 종료. 같은 기존 폴더에서 동일 명령으로 다시 실행할 수 있음.

실행 안내 상세판: [OLPOT_FIRST_RUN.md](./OLPOT_FIRST_RUN.md).

**이 문서를 새로 추가한 브랜치의 최신 커밋은 위의 5일차 SHA와 달라진다.** 문서 커밋 뒤 최종 브랜치와 40자리 커밋 번호를 다시 확인하여 제출해야 한다. **PC의 로컬 `HEAD`가 원격 최종 커밋과 같다고 주장하지 않는다.**

기존 프로젝트의 `STUDENT_RUNBOOK.md` 수정본, 22단계 재현 기록, `.bak` 등은 **보존**한다. `git reset --hard`, `git push --force`, 광범위한 `git add .`는 사용하지 않는다.

## 8. 결론

olpot 완성본은 **기존 제공 로컬 PC 데이터 수집 기능을 바탕으로**, 학생 영역에 **실측 비교·추이·기록과 다음 행동**을 정리한 관제 대시보드다. **네 상태 카드가 먼저, 아래 비교·추이·기록이 나오는 구조**를 실제 사용자 화면에서 확인했다.

검증한 것은 실제로 확인한 범위까지만 설명한다. **SDP 원천 연결, XDR 침해 탐지, 전체 안전 판정, 설치형 앱 포장·설치는 이번 시연 결과로 주장하지 않는다.**
